# N60 相控阵 · 计算原理说明（小白版）

> 本文配合 `generate_n60_csv.py` 和 `n60_beam_params.py` 阅读。
> 目标读者：完全没接触过相控阵 / 波束成形的人。
> 读完本文，你会明白：**界面上拖一个滑块，程序到底算了什么、怎么算的、最后发给 FPGA 的是什么。**

---

## 0. 一句话总结

**相控阵 = 让 60 个麦克风"假装"是一支可以遥控方向的电子枪。**

- 每个麦克风的声音信号，我们先给它们不同的**时间延迟**（用"相位"表示）和**大小**（用"幅度"表示）；
- 延迟决定了波束**往哪个方向看**（聚焦点在哪）；
- 幅度决定了**看得多集中**（不想听的方向被压得多狠）；
- 算好之后，把 60 个"延迟值 + 幅度值"打包成一串字节，通过串口发给 FPGA 执行。

---

## 1. 硬件长什么样（先建立空间概念）

### 1.1 三个坐标系名词

| 名词 | 含义 |
|------|------|
| 阵元 (element) | 一个麦克风，一共 **60 个**，编号 ch = 0 ~ 59 |
| 子阵 (unit) | 5 组麦克风，每组 **12 个**。60 = 5 × 12 |
| 通道 (channel) | 就是"路"的意思，第几路信号。ch 与 (子阵, 阵元) 的对应关系：`unit_id = ch // 12`，`elem_id = ch % 12` |

### 1.2 碗是怎么摆的

5 个子阵整体分别朝水平方向偏转：

```
-45°   -22.5°   0°   +22.5°   +45°
  \      \      |      /      /
   \      \     |     /     /
    \______\____|____/____/     ← 5 组麦克风，围成扇形
```

12 个阵元在子阵内部按特定间距排成 3 圈（见代码里的 `N12_LOCAL_COORDS`），
所有 60 个阵元的中心都落在**半径为 176.445 毫米的球面**上，所以整体是个"碗"。

### 1.3 空间坐标系

- 原点 `(0,0,0)` 在**碗的曲率中心**（碗口前方约 176mm 的虚拟点）；
- **x 轴**：左右（正 = 右）；
- **y 轴**：上下（正 = 上）；
- **z 轴**：前后（正 = 目标方向 / 前方）。

> ⚠️ 单位注意：`generate_n60_csv.py` 里坐标用**米**，`n60_beam_params.py` 里用**毫米**。
> 两个文件里 `generate_n60_geometry()` 功能相同但单位不同，看代码时别混。

## 2. 三个必须懂的核心概念

### 2.1 为什么给信号加"延迟"就能转向？（相位 / 延迟）

想象 60 个人站成一排，你站在他们正前方喊"一、二、三——一起喊！"。
他们同时开口，声音同时到达你耳朵 → 你听到的声音最大（聚焦成功）。

现在你想让这排人**朝右边 30° 的方向"喊"**，怎么办？
让**左边的人先开口，右边的人后开口**，这样声波阵面就歪向右边了。

麦克风接收方向同理（时间反演）：
- 声音从目标点传到每个阵元的路程**不一样长**；
- 路程远的阵元，声音**先到**（相位超前）；
- 我们要让 60 路信号"到达目标点时刚好对齐"，就得给**近的阵元多延迟、远的阵元少延迟**；
- 代码里用 **phase（相位）** 表示这个延迟，范围 0 ~ 2499（一个完整周期的 2500 等份）。

### 2.2 为什么给信号加"幅度"？（幅度加权 / 指向性）

单个麦克风不是全方向一样灵敏的：**正对着它的声音最灵（增益 = 1.0），
偏 35° 灵敏度掉一半（-6dB）**，再偏就更弱——这叫"指向性"。

这反而帮了忙：碗是弯的，总有一些阵元"正对"目标点（该给大幅度），
另一些阵元"斜对"目标点（该给小幅度）。按这个规律给每路加权，
就能进一步压低"旁瓣"（不想听的方向上的杂音），让波束更集中。

### 2.3 相位和幅度的分工

| 参数 | 控制什么 | 谁决定它 |
|------|----------|----------|
| 相位 phase (0~2499) | 波束**指向哪里**（聚焦点位置） | 每路阵元到目标点的**路程差** |
| 幅度 amp (0~255) | 波束**有多集中**（旁瓣压得多狠） | 阵元表面朝向与目标方向的**夹角**（三种模式） |

## 3. 计算流程总览

```
用户拖滑块(距离/角度/模式)
        │  valueChanged 信号
        ▼
① 角度限幅：把方向压进 ±30°   ── limit_direction_n60()
        │
        ▼
② 定目标点：距离 × 方向 = 目标点三维坐标
        │
        ▼
③ 逐路算相位：每路声程差 → 相位值 (0~2499)   ── 60 路循环
        │
        ▼
④ 逐路算幅度：三种模式选其一 → 幅度值 (0~255)
        │
        ▼
⑤ 打包成数据帧 + 校验和                    ── make_packet()
        │
        ▼
⑥ 串口发送给 FPGA                          ── send_to_fpga()
```

下面每一步详细展开。

---

## 4. 第一步：角度限幅（为什么最大只能偏 30°？）

用户可以把水平角和俯仰角都拉到 30°。
但两个方向都偏 30°，**合成方向其实偏了约 43°**，超过硬件能力。

所以程序先做"压缩"（`limit_direction_n60`）：

1. 把角度转成方向向量的两个分量：`sx = sin(水平角)`，`sy = sin(俯仰角)`；
2. 算出合成偏移量：`sxy = √(sx² + sy²)`；
3. 允许的上限：`max_s = sin(30°) ≈ 0.5`；
4. 如果 `sxy > 0.5`，就按比例缩小：`sx' = sx × (0.5 / sxy)`，`sy'` 同理；
   —— 方向不变，只是角度变小，这就是"限幅"；
5. 反推出第三个分量 `sz = √(1 - sx² - sy²)`，保证方向向量长度 = 1；
6. 把压缩后的值反算成角度，显示在界面上（触发限幅时会有橙色警告）。

> 直观理解：把"方向"想成一根射出去的箭，超出 30° 就把箭**按原方向缩短**，
> 而不是硬掰到别的角度。

---

## 5. 第二步：定目标点（聚焦点在哪）

```
distance_m = 距离(毫米) / 1000          # 换算成米
target_m   = ( distance_m × sx ,      # x = 左右
               distance_m × sy ,      # y = 上下
               distance_m × sz )      # z = 前后
```

- `sx, sy, sz` 是上一步限幅后的单位方向向量（长度 = 1）；
- 距离 × 方向 = 目标点在空间中的绝对坐标（米）。

例子：距离 1 米、水平角 0°、俯仰角 0° → 目标点 = `(0, 0, 1.0)` 米，就在碗正前方 1 米处。

---

## 6. 第三步：算 60 路相位（核心之一）

对每个通道 ch 单独算：

```
阵元坐标（毫米）→ 除以 1000 换成米： (mx, my, mz)

声程 path_m = √( (tx - mx)² + (ty - my)² + (tz - mz)² )     # 目标点到这个阵元的真实距离

相位周期数 = (path_m - distance_m) × CARRIER_HZ ÷ SOUND_SPEED_M_S
           = 路程差(米) × 40000 ÷ 343
```

### 6.1 为什么这么算？拆开看

- `路程差 = path_m - distance_m`：这个阵元比"参考点"（原点处）远多少米；
- `路程差 ÷ 声速(343 m/s)` = 声音多花多少**秒**；
- `秒数 × 载波频率(40000 Hz)` = 这段时间里走了多少个**波长周期**；
- 所以"相位周期数"就是：**这路信号要比参考信号提前/滞后多少个完整波形**。

### 6.2 为什么要取小数部分？

波形是**周期性重复**的：超前 1.3 个周期和超前 0.3 个周期，效果完全一样
（多的那 1 个整周期等于没偏）。所以：

```
phase = round( 相位周期数 的小数部分 × 2500 ) % 2500
```

把"0~1 个周期"切成 FPGA 能懂的 2500 等份（`PWM_PERIOD_TICKS = 2500`），
得到最终相位值 0 ~ 2499。

> 直觉：**远的阵元先收到声音 → 相位算出来是"超前" → 取小数后折回**，
> 最终表现为给近的阵元补延迟，让波前在目标点对齐。

---

## 7. 第四步：算 60 路幅度（三种模式）

### 模式 1：物理法向 3.5 次方加权（默认，实时计算）

```
① 阵元法向量（麦克风表面"朝向"）：
   nx = -sin(子阵偏角θ)
   ny = 0
   nz =  cos(子阵偏角θ)

② 阵元 → 目标的方向向量（归一化成单位长度）：
   v = (目标 - 阵元) ÷ 距离

③ 点积（两个单位向量的夹角余弦）：
   dot = vx·nx + vy·ny + vz·nz
       = cos(阵元朝向 与 目标方向 的夹角)
       → 正对 = 1，垂直 = 0，背对 < 0

④ 幅度 = max(0, dot) ^ 3.5
```

**3.5 次方是哪里来的？** 来自原厂麦克风实测数据：`-6dB @ 35°`（偏 35° 灵敏度减半）。
用这个幂次能把真实的指向性衰减曲线拟合得很接近。

为什么用 3.5 次方而不是直接点积？
因为麦克风指向性本来就衰减，再**人为加速衰减**（3.5 次方让偏离目标的角度掉得更快），
旁瓣会被压得更干净。

### 模式 2：离线优化表（查表）

`generate_n60_csv.py` 提前算好一张表：**6 种距离 × 13 种角度 = 78 个目标点，
每个目标点存 60 个幅度**。

运行时按 (距离, 角度) 用**最近邻**原则找最接近的一行，直接取表里的 60 个幅度
（`load_optimized_table`）。找不到表文件就退回全 1（不衰减）。

> 表和实时计算的区别：表是"提前优化过的"（可以人工调参、固化最优解），
> 实时计算是"现场按物理公式现算"。两者数学原理相同。

### 模式 3：全通（仅测总功率）

所有幅度 = 1.0，等于不加权，用来测试设备总功率是否正常。

### 幅度换算给 FPGA

```
0.0 ~ 1.0 的小数  →  ×255 → 四舍五入 → 0 ~ 255 的整数
```

## 8. 第五步：打包成数据帧（FPGA 听得懂的语言）

FPGA 只认二进制字节，所以要把 60 个幅度 + 60 个相位按**约定的格式**排好：

```
┌────────┬────────┬──────────────────┬──────────────────┬──────────┬────────┬────────┐
│ 帧头   │ 指令码 │ 60 个幅度         │ 60 个相位         │ 校验和   │ 帧尾   │        │
│ 0xAA   │ 0x01   │ 每路 1 字节       │ 每路 2 字节(小端) │ 1 字节   │ 0x0D   │ 0x0A   │
│ 0xBB   │        │ 0~255             │ 0~2499            │          │        │        │
└────────┴────────┴──────────────────┴──────────────────┴──────────┴────────┴────────┘
```

| 字段 | 大小 | 说明 |
|------|------|------|
| 帧头 `0xAA 0xBB` | 2 字节 | 固定，FPGA 靠它认出"数据开始了" |
| 指令码 `0x01` | 1 字节 | 固定，表示"更新参数"这个命令 |
| 60 个幅度 | 60 字节 | 每路 1 字节，0~255 |
| 60 个相位 | 120 字节 | 每路 2 字节，**小端序**（低字节在前），0~2499 |
| 校验和 | 1 字节 | 指令码之后所有字节求和，取低 8 位（`sum(packet[2:]) & 0xFF`），用于查错 |
| 帧尾 `0x0D 0x0A` | 2 字节 | 回车+换行，表示"数据结束" |

总长度 = 2 + 1 + 60 + 120 + 1 + 2 = **186 字节**。

## 9. 一个完整的手算例子（建议跟着算一遍）

**条件**：距离 1000 mm（1 米），水平角 0°，俯仰角 0°。
目标点 = `(0, 0, 1.0)` 米。

取 **ch = 0**（子阵 0，偏角 -45°，局部坐标 (0,0) 即子阵中心阵元）：

### 9.1 算阵元坐标

```
子阵0 中心：cx = 176.445 × sin(-45°) ≈ -124.77 mm
            cz = -176.445 × cos(-45°) ≈ -124.77 mm
阵元坐标（毫米）：(-124.77, 0, -124.77)
换成米：        (-0.12477, 0, -0.12477)
```

### 9.2 算相位

```
声程 = √( (0-(-0.12477))² + (0-0)² + (1-(-0.12477))² )
     = √( 0.01557 + 0 + 1.26511 )
     = √1.28068 ≈ 1.1317 米

相位周期数 = (1.1317 - 1.0) × 40000 ÷ 343
           = 0.1317 × 116.62 ≈ 15.35 个周期

取小数部分：0.3544
相位 = round(0.3544 × 2500) % 2500 = 886
```

→ 这个阵元比参考点多走了约 0.13 米，声音会**先到**，
给它的延迟对应 886/2500 个周期。

### 9.3 算幅度（模式 1）

```
法向量（子阵 -45°）：nx = -sin(-45°) ≈ 0.7071
                     nz =  cos(-45°) ≈ 0.7071

阵元 → 目标方向 = (0.12477, 0, 1.12477)，长度就是声程 1.1315
归一化：v ≈ (0.1103, 0, 0.9939)

点积 dot = 0.1103×0.7071 + 0 + 0.9939×0.7071 ≈ 0.781

幅度 = 0.781 ^ 3.5 ≈ 0.42
→ 换算成 0~255：round(0.42 × 255) ≈ 107
```

→ 这个阵元朝向和目标方向夹角约 38.6°，所以幅度只给到约 42%（107/255）。

### 9.4 换一个角度感受差异

如果目标点改成**正对着子阵 0 的方向**（比如 az = -45° 附近），
点积会更接近 1，幅度接近 255；离目标远的子阵点积变小甚至为负（取 0），
幅度为 0 —— **这就是"只有正对目标的阵元才出力"的物理本质。**

## 10. 界面操作 → 硬件动作 完整链路（数据流）

```
你拖动"水平角"滑块
  → Qt 发出 valueChanged 信号
  → calculate_array() 被调用（限幅 → 定目标 → 算 60 路相位 → 算 60 路幅度）
  → 界面 60 个格子实时变色（幅度大 = 亮青色）
  → 如果勾了"自动同步"：启动 120ms 防抖定时器
      → 120ms 内你没再动 → 定时器触发 → make_packet() 打包
      → SerialLogic.send() 通过串口发 186 字节给 FPGA
      → 日志框显示帧内容（十六进制）
```

**为什么有 120ms 防抖？** 拖动滑块会触发几十次计算，如果每次立刻发串口包，
FPGA 会被刷爆。所以"停手 120ms 后才发一次"。

**自动扫描模式**则是把这件事自动化：每 1 秒把水平角 +2°，
触发同一套链路，实现波束自动从 -30° 扫到 +30° 再扫回来。

## 11. 术语速查表

| 术语 | 通俗解释 |
|------|----------|
| 相位 phase | 延迟的大小，0~2499，控制波束方向 |
| 幅度 amp | 音量大小，0~255，控制波束集中度 |
| 波束成形 | 用延迟+幅度让阵列"指哪听哪"的技术 |
| 旁瓣 | 主方向之外的杂散灵敏度，要尽量压低 |
| 指向性 | 麦克风对不同方向灵敏度不同 |
| 法向量 | 垂直于麦克风表面的方向，即它"朝向"哪 |
| 点积 dot | 两个方向的"夹角余弦"，同向=1，垂直=0 |
| 最近邻查表 | 在表里找与目标最接近的一行 |
| 小端序 | 2 字节数字低字节在前（Intel 和常见单片机都这样） |
| 校验和 | 数据求和取低 8 位，接收方重算比对，检查传输错误 |
